## [핵심 내용]
"Claude를 Hyperliquid에 연결했다"는 콘셉트의 인포그래픽 캐러셀이다. 역할 분담은 'Claude = 추론, Hyperliquid = 시세·체결'이다. 흐름은 다섯 단계로 그려진다. ① 시장 스캔(SCAN → ANALYZE → EXECUTE), ② 리스크 산정(포지션 크기, 레버리지, 증거금, 손절, 청산 버퍼), ③ 트레이드 플랜(진입, 손절, 목표가, 근거), ④ 다중 시장 감시(펀딩비, 미결제약정, 오더북, 청산), ⑤ 포지션 추적(PnL, 바이어스 변화, 스탑 이동, 청산 로직)이다. 마지막 장은 팔로우 유도다. 캡션의 핵심 메시지는 한 줄로 요약된다. "어려운 건 리스크 규칙이 모델의 자신감보다 강하게 만드는 것." 슬라이드의 시세, 포지션, 손익은 모두 연출된 예시 화면이다. 실제 연결 방법(MCP 서버, API 지갑), 프롬프트, 체결 기록은 없다.
- 슬라이드 5(사용자 지정, "IT TRACKS THE POSITION"): 이 게시물에서 가장 쓸 만한 장이다. HYPE 롱 포지션의 하루 운용을 타임라인으로 보여 준다. 진입 24.10(10:14) → 논지 유지, PnL +4.1%(11:22) → 스탑을 24.80으로 상향(12:37) → 26.00에서 50% 부분 익절(14:03) → 모멘텀 약화로 청산 신호(15:28). 이어서 "모멘텀이 강해지면 / 약해지면" 두 갈래로 다음 행동 규칙을 제시한다. 강해지면 스탑을 25.80으로 올리고 추가 진입을 검토하며 28.40 이상을 노린다. 약해지면 스탑을 조이고, 붕괴 시 전량 청산하며, 새 셋업 전에는 재진입하지 않는다. LLM 에이전트에게 '열린 포지션 관리' 규칙을 어떻게 문서화할지 보여 주는 템플릿으로 참고할 만하다. 다만 화면 숫자 자체는 앞뒤가 맞지 않는다(아래 참조).

## [확인할 가치가 있는 부분]
- 웹 확인(2026-10-12): Claude와 Hyperliquid 연결 자체는 실제로 가능하다. 오픈소스 Hyperliquid MCP 서버가 여럿 공개되어 있다(edkdev/hyperliquid-mcp, 0xikalgo/hyperliquid-mcp, Dakkshin/hyperliquid-mcp 등). 이 서버들은 공식 Python SDK 기반으로 시세, 오더북, 펀딩, 주문, 포지션 기능을 제공한다. 공통 권고는 세 가지다. 메인 지갑 대신 출금 권한이 없는 'API(에이전트) 지갑'을 쓸 것(최대 180일 유효), 테스트넷에서 먼저 돌릴 것, 메인넷 주문에는 사람 승인을 유지할 것. 게시물은 이 보안·권한 설계를 전혀 다루지 않는다.
- 시세 불일치: 슬라이드의 HYPE 가격은 24~26 USDC대다. 게시일(2026-09-29) 실제 HYPE 종가는 약 $86(일중 약 $84.8~$90.7)이었다. 차트 날짜도 'Apr 6–10'이다. 실제 계좌 화면이 아니라 만들어 낸 목업이라는 뜻이다.
- 슬라이드 2 리스크 표의 내부 모순:
  - Max Risk: 10,000 USDC 포지션을 24.80에 진입해 23.10에서 손절하면 손실은 약 685 USDC다. 표에 적힌 340 USDC가 아니다.
  - R/R: (28.40−24.80)/(24.80−23.10)으로 계산하면 약 2.1:1이다. 표의 3.6:1이 아니다.
  - 청산가: Hyperliquid 공식 문서의 청산가 공식으로 격리 5x를 가정하면 약 20.9~22.0 USDC다(HYPE 최대 레버리지 10x~5x, 즉 유지증거금률 5~10% 가정). 표의 18.60은 이 가정과 맞지 않는다. 교차 마진이면 계좌 잔고에 따라 달라진다.
- 슬라이드 3: 진입 26.10–26.40, 손절 23.00, 목표 30.00이면 R/R은 약 1.15:1이다. 표기된 3.2:1과 다르다.

## [현재 프로젝트와 연결 가능성]
- AI 봇/도구: 이사님의 Grok Bot/Claude 에이전트 설계에 바로 쓸 수 있는 아이디어는 두 가지다.
  - '리스크 규칙 > 모델 자신감' 원칙. 사이징, 손절, 최대손실 계산은 LLM이 아니라 결정론적 코드로 강제하고, LLM은 셋업 판단과 서술만 맡긴다. 이 게시물의 숫자 오류가 바로 LLM이나 디자인 툴에 계산을 맡겼을 때 생기는 문제를 보여 준다.
  - 슬라이드 5식 포지션 관리 플레이북(이벤트 타임라인 + 강세/약세 분기 규칙)을 에이전트 시스템 프롬프트의 규칙 섹션으로 옮기는 것.
  - 이 박스에는 이미 Phantom(perps 도구 포함)과 Aave 같은 온체인 연결이 있다. 실험한다면 테스트넷 또는 페이퍼 모드, 출금 불가 API 지갑, 주문 전 사람 승인 구조를 전제로 해야 한다.
- 투자: BTC와 크립토 노출 관리에 '진입 전 R/R·청산가·최대손실 자동 검산' 체크리스트로 응용할 수 있다. 한국 주식이나 MSTR에는 레버리지 부분을 빼고 사이징·스탑 규칙만 참고하면 된다.
