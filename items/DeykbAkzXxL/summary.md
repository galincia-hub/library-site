## 핵심 요지
Claude 사용량이 빨리 바닥나는 원인은 '많이 써서'가 아니라 불필요한 파일 탐색과 원본 로그·출력을 그대로 주고받는 토큰 낭비라는 주장. 이를 줄이는 Claude Code 플러그인 3종을 소개한다. 영상이 다루는 것은 프롬프팅 기법이 아니라 도구다. 다만 각 도구의 원리는 프롬프트 원칙으로 옮겨 쓸 수 있다.

## 주요 내용
1. **Ponytail(포니테일)** (github.com/DietrichGebert/ponytail): "가장 게으른 시니어 개발자처럼" 최소 구현(YAGNI)을 하도록 에이전트를 유도하는 스킬/플러그인. 원리: **출력 최소화**.
2. **Graphify** (github.com/Graphify-Labs/graphify): 코드베이스·문서를 로컬 지식그래프(graph.json)로 만든다. Claude가 grep이나 파일 통독 대신 그래프를 질의해 필요한 부분만 읽게 한다. 원리: **지도 먼저, 필요한 곳만 읽기**.
3. **Headroom** (github.com/headroomlabs-ai/headroom): 도구 출력·로그·RAG 청크·대화 이력을 LLM에 보내기 전에 로컬에서 압축하는 프록시/MCP. 원본은 필요할 때 다시 꺼낼 수 있다(CCR). 원리: **입력 압축, 필요한 부분만 통과**.
- 영상 말미에서 세 가지를 한 번에 설치하는 가이드를 홍보한다(제거).

## 수치/주장 확인
- "Ponytail GitHub 9만 스타": 이번에 별도 확인하지 못함(미검증). 인기 저장소인 것은 맞다.
- "Ponytail이 사용량을 50% 넘게 줄인다(화면 128K→52K, -59%)": **과장**. 공식 벤치(2026-10-07, 39과제, Opus 5.5)는 출력 토큰 -45%, 비용 -26%, 코드 -53%다. JetBrains 독립 테스트(80과제)는 비용 -10.3%, 코드 -15%에 그쳤다. 절감 효과는 과잉 구현 성향이 큰 과제에 집중된다.
- "Graphify를 쓰면 토큰을 70% 넘게 덜 쓴다": **근거가 다름**. 공식 '71.5배'는 전체 파일 통독과 그래프 질의를 비교한 추정치(단어/문자 기반 추산)이고, 실제 엔드투엔드 측정이 아니다. ERPNext 에이전트 비교(Graphify 측 게시)에서는 정확도 82% vs 70.8%(+11pt)였지만 비용은 사실상 같았다($0.320 vs $0.322). "70% 절감"이 일반적으로 성립한다고 보기 어렵다.
- "Headroom이 불필요한 줄을 압축해 같은 결과": **부분 사실**. JSON 도구 출력·로그·긴 세션에서 효과가 크다. 소스코드, 짧은 메시지, 시스템 프롬프트, grep 결과는 대부분 압축하지 않는다(공식 Limitations). 압축은 로컬에서 하고 원본은 복구할 수 있다.
- "며칠 만에 바닥나는 건 토큰 누수 때문": 의견. 일리는 있지만 정량 근거는 제시하지 않았다.
