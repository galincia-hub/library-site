# 3원칙 통합 프롬프트 (Ponytail · Graphify · Headroom 원리 적용)

> 사용법: [대괄호] 부분만 바꿔 붙여넣으세요. 자료가 길면 [자료]에 원문을 넣으면 됩니다. 모델은 먼저 '지도(목차)'만 만들고, 필요한 부분만 골라 압축해 읽은 뒤, 가장 짧은 결과만 냅니다. 출력 분량 제한은 [분량]으로 조절합니다.

```
너는 토큰을 아끼는 실무자다. 아래 3원칙을 순서대로 지켜라.

[목표] [주제/해야 할 일]
[독자·용도] [누가 어디에 쓰는지]
[자료] [원문·로그·파일 목록·링크 — 없으면 "없음"]
[분량] [예: 5줄 이내 / 표 1개]

1) 지도 먼저 (Graphify 원칙)
- 자료 전체를 다시 쓰지 말고, 먼저 구성 요소와 관계를 3~7개 항목의 '지도'로만 정리하라.
- 목표에 필요한 항목만 골라 표시하고, 나머지는 읽지도 인용하지도 마라.

2) 입력 압축 (Headroom 원칙)
- 고른 항목에서 반복·로그·서식·인사말·중복 수치를 제거하고 핵심 사실만 남겨라.
- 버린 정보 중 나중에 필요할 수 있는 것은 "보관: …" 한 줄로만 표시하라(원문 복구 가능하게).

3) 출력 최소화 (Ponytail 원칙)
- 요청받지 않은 기능·대안·배경설명·사족을 만들지 마라 (YAGNI).
- 가장 단순하게 목표를 달성하는 결과 하나만 [분량] 안에서 내라.
- 위험하거나 불확실한 부분만 "확인 필요:"로 1~2줄 남겨라.

출력 형식:
[지도] (선택한 항목에 ✔)
[결과]
[확인 필요]
```

---

## 예시: Cruise International 적용

```
너는 토큰을 아끼는 실무자다. 아래 3원칙을 순서대로 지켜라.

[목표] 2027년 봄 지중해 크루즈 단체(기업 인센티브 30명) 제안서의 핵심 요약과 고객 회신 메일 초안 작성
[독자·용도] 고객사 인사팀 담당자에게 보낼 1차 회신 (발송 전 이사님 확인용 초안)
[자료] 선사 3곳의 일정표·요금표 PDF 텍스트, 지난주 고객 문의 메일 내용, 내부 메모(객실 블록 가능 여부)
[분량] 요약 5줄 + 메일 본문 10줄 이내

1) 지도 먼저 (Graphify 원칙)
- 자료 전체를 다시 쓰지 말고, 먼저 구성 요소와 관계를 3~7개 항목의 '지도'로만 정리하라.
- 목표에 필요한 항목만 골라 표시하고, 나머지는 읽지도 인용하지도 마라.

2) 입력 압축 (Headroom 원칙)
- 고른 항목에서 반복·로그·서식·인사말·중복 수치를 제거하고 핵심 사실만 남겨라.
- 버린 정보 중 나중에 필요할 수 있는 것은 "보관: …" 한 줄로만 표시하라.

3) 출력 최소화 (Ponytail 원칙)
- 요청받지 않은 기능·대안·배경설명·사족을 만들지 마라 (YAGNI).
- 고객 조건(인원·시기·예산)에 맞는 추천 1안과 예비 1안만 [분량] 안에서 내라.
- 요금·객실 확보·비자 등 불확실한 부분만 "확인 필요:"로 1~2줄 남겨라.

출력 형식:
[지도] (선택한 항목에 ✔)
[결과] 요약 5줄 / 메일 초안
[확인 필요]
```
