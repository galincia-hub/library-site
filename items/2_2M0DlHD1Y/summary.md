# Shadcn Lint 써서 AI로 디자인 박살내지 않기

- 채널: 코드팩토리 · 업로드 2026-10-05 · 7:08
- URL: https://www.youtube.com/watch?v=2_2M0DlHD1Y
- 키워드: shadcn/ui, shadcn lint(@shadcn/lint), Tailwind 테마 토큰(primary 등), 디자인 시스템 일관성, AI 코딩 에이전트 오버라이드, 빌드 전 린트 검사, 린트 진단 → LLM 수정 루프, 기존 프로젝트 도입 프롬프트
- Research Level: 1
- 텍스트: YouTube 자동자막 (whisper 미실행: box 메모리 부족, 숫자 위주 구간도 없음)

## [핵심 내용]
AI로 웹사이트를 만들다 보면 페이지를 추가하거나 고칠 때마다 색·글꼴·여백이 제멋대로 바뀌어 디자인이 무너진다. 원인은 LLM이 테마에 없는 색이나 스타일을 마구 덮어쓰기(오버라이드) 때문이다. 영상은 새로 나온 shadcn lint로 이런 코드를 빌드 전에 잡아내고, 린트 진단(어느 파일의 어떤 코드를, 테마·컴포넌트의 무엇으로 바꿀지)을 AI에 그대로 넘겨 고치게 하는 흐름을 소개한다. 7분짜리 개념 소개 영상이라 실제 설정 파일이나 명령어는 거의 나오지 않는다.

## [주요 주장]
- 사실(화자 설명, 일부 웹으로 확인):
  - shadcn/ui는 기본 스타일이 잡힌 UI 컴포넌트 코드를 내 프로젝트에 복사해 직접 고쳐 쓰는 방식이다. 색상은 배경·글자·강조(primary)처럼 역할별 이름의 테마 값으로 관리하므로, 강조색 하나만 바꿔도 그 값을 쓰는 모든 컴포넌트가 함께 바뀐다. 모서리 둥글기와 글자 스타일도 공통 설정으로 관리된다.
  - 코드에 분홍색을 직접 넣어 두면 테마를 초록색으로 바꿔도 그 부분만 분홍색으로 남는다(테마 이탈).
  - shadcn lint의 색상 규칙을 켜고 실행하면 잘못 넣은 색상 코드가 진단에 나오고, 대신 쓸 수 있는 테마 색 이름과 그 색을 정의한 파일까지 알려 준다. 공통 컴포넌트의 크기나 색을 사용하는 쪽에서 덮어쓴 경우에도, 그 컴포넌트에 정의된 크기·스타일 선택지를 진단으로 보여 준다.
- 의견:
  - 사람이 직접 코딩할 때는 오버라이드를 예외적으로만 썼지만, 요즘 LLM은 무차별적으로 쓴다.
  - "기존 디자인이랑 맞춰 줘"처럼 대충 부탁하면 멀쩡하던 부분까지 바뀐다. 린트 진단으로 정확한 위치와 대안을 주는 게 낫다.
  - 린트를 빌드 전 검사에 연결해 두면, AI가 규칙을 어겨도 에러로 바로 드러나 근거를 가지고 고칠 수 있다.
  - 기존 프로젝트 도입 순서(화자 권장 프롬프트): ① 현재 테마와 공통 컴포넌트 위치를 AI에게 확인시킨다. ② 공식 설치 안내 링크를 주고 "현재 프로젝트에 맞게 설치·등록하되 기존 검사 설정은 유지해 줘"라고 요청한다. ③ 테마 색 사용 여부와 컴포넌트 외관 덮어쓰기를 검사하는 규칙을 설정하고 검사 명령을 받는다. 일부러 넣은 오버라이드는 제외한다. ④ "수정 → 린트 재실행 → 진단 수정"을 진단이 없어질 때까지 반복시킨다.
- 전망:
  - 일단 정리해 두면 앞으로는 린트만 돌려도 문제 부분을 한 번에 찾을 수 있다.
- 가설:
  - 린트 진단을 LLM에게 먹이면 대충 요청할 때보다 수정이 빠르고 정확해진다. 영상에는 정량 근거가 없다. shadcn 측이 자체 평가에서 수정 1회 만에 해결되고 비용이 10~48% 줄었다고 주장한 바 있으나, 이는 개발사 자체 발표라 근거가 약하다.

## [확인할 가치가 있는 부분]
- 웹 확인(2026-10-08): 정식 명칭은 `@shadcn/lint`(GitHub shadcn-ui/lint, MIT, 2026-09 공개). Tailwind v4 프로젝트용이고, shadcn/ui가 없어도 쓸 수 있다. ESLint 9.30+ 또는 Oxlint 1.80+ 플러그인으로 동작하며, Node.js 20.19 이상이 필요하다. 규칙은 no-restyle, no-raw-colors(예: `bg-pink-500`), no-arbitrary-values, no-inline-styles, no-unknown-classes, require-static-classes. 영상에서 말한 '색상 검사'는 no-raw-colors, '컴포넌트 덮어쓰기 검사'는 no-restyle에 해당하는 것으로 보인다.
- 제약(외부 리뷰 기준, 미검증): Tailwind v3 프로젝트는 대상이 아니다. Oxlint의 JS 플러그인 API는 아직 alpha라 ESLint 쪽이 안정적이라는 평가가 있다. Vue·Svelte 지원은 공식 문서와 리뷰가 엇갈린다. 버전이 0.2.0 수준이라 이슈가 계속 올라오는 중이다.
- 영상은 설정 파일(.oxlintrc.json / eslint config)과 AGENTS.md 연동 같은 구체적 내용을 보여 주지 않는다. 실제 도입하려면 공식 README를 봐야 한다.
- 자막 오인식(추정): "샤스앤/샤시엔/샷시앤/샤센/샤스/샤시"=shadcn, "린트/링트/트"=lint, "LRM/LM"=LLM, "에아"=AI, "강지"=강제, "빌드에처럼"=빌드 에러처럼, "세 페이지"=새 페이지, "벗퍼 쓰고"=덮어 쓰고, "차아 줘요"=찾아 줘요, "기종 테마"=기존 테마. 미확인: 끝인사의 "하이보이"(알림 설정으로 추정), "So easy/쏘지".
- 홍보성 내용 제외: 구독·좋아요·알림 요청, "작년부터 계속 가르쳐 드리고 있다"는 채널 강의 언급.

## [현재 프로젝트와 연결 가능성]
- AI 봇/도구: 이사님이 AI 에이전트로 만드는 사이드 프로젝트 웹페이지나 대시보드가 Tailwind v4 + shadcn/ui라면 바로 쓸 수 있다. AGENTS.md에 "npm run lint 실행 후 에러 0까지 수정"을 넣어 두면 에이전트가 스스로 검증하는 루프가 된다. 봇 여러 개가 같은 저장소를 고칠 때 디자인이 흩어지는 문제를 막는 가드레일로 쓸 만하다.
- 크루즈 사업: Cruise International 프로모션·랜딩 페이지를 AI로 여러 장 찍어낼 때 브랜드 컬러와 톤을 고정하는 장치로 응용할 수 있다. 다만 회사 사이트 스택이 Tailwind v4인지에 달려 있다.
- Threads 마케팅: 직접 연관은 없다. 'AI가 만든 디자인이 페이지마다 달라지는 문제' 자체는 개발·AI 활용 콘텐츠 소재가 될 수 있다.
- 투자: 연관 없음.
