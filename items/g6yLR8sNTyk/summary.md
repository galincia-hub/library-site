## 1. 핵심 요지
외주 개발사 리트머스가 GitHub에서 화제가 된 오픈소스 REA를 Claude Code·Codex에 붙여 엑셀·원노트·파워포인트·워드·캡컷을 "역공학"으로 다시 만들어 봤다. 화면은 비슷하게 나왔지만 실제 쓸 만한 수준은 아니었다(독립 QA 점수 10점 만점에 2~5점). 그런데 노션은 방식을 바꿨다. 소스코드는 손대지 않고, 공개 사용설명서·업데이트 로그·브라우저에서 보이는 API 요청/번들로 기능 명세 약 3,000개를 먼저 만든 뒤 에이전트를 여러 라운드 돌렸고, 그 결과 QA 점수가 100점 만점에 38점에서 96점까지 올랐다고 한다. 결론은 두 가지다. 같은 AI라도 "요구사항→명세→독립 테스트→반복" 워크플로를 어떻게 짜느냐에 따라 결과 차이가 크다. 그리고 프론트·기능은 베낄 수 있어도 동시 편집 싱크, 권한, 외부 연동 같은 서버 쪽은 베끼기 어렵기 때문에 그 부분이 소프트웨어의 해자로 남는다. 노션 클론은 Litpage라는 이름의 MIT 오픈소스로 공개했다.

## 2. 주요 내용 (타임스탬프)
- 00:25 REA 소개: 기존 역공학 도구(Ghidra, IDA Pro 등)를 Claude Code·Codex에서 쓸 수 있도록 스킬/MCP로 묶은 오픈소스다. "언제 어떤 툴을 써라" 정도의 지침이 들어 있고, 바이럴이 컸다.
- 00:59 리버스 엔지니어링 정의: 이미 만들어진 결과물을 보고 어떻게 만들었는지 파내는 것.
- 02:03 엑셀: React+Electron 데스크톱 앱으로 재현했고 내부 DB는 SQLite를 썼다. 복사, SUM 함수, 서식, 셀 병합, 피벗 테이블(수기 입력)은 된다. 자동완성과 채우기 드래그는 안 되고, 수식 50개 이상 시트처럼 성능 설계가 필요한 부분도 안 된다. 독립 기능 테스트 **5/10점**.
- 03:55 테스트 방식: 테스트를 미리 만들어 두고 개발 에이전트에게는 보여 주지 않는 독립 QA 구조.
- 04:27 원노트: 화면과 MS 디자인 느낌, 심지어 불편한 점까지 그대로 재현했다. 탭 들여쓰기와 스크린샷 삽입은 안 됐다. 약 5/10점. 무료 버전으로 분석해서 유료 기능은 못 봤을 수 있다고 함.
- 05:41~06:13 MS 앱들에 에이전트를 "100시간 넘게" 돌렸고 비용을 많이 썼다고 언급(설명란 챕터 제목은 "2만 불").
- 06:14 파워포인트: 삽입과 슬라이드쇼는 되지만 도형·아이콘·애니메이션 재현이 약하고, 크기 조절과 표 편집이 안 된다. 4.5점으로 나왔지만 화자들은 "사실상 2점"이라고 평가.
- 07:57 워드: 무료 버전은 읽기 전용이라 편집 기능은 추론해서 만들었다. 표, 행·열 추가, 페이지, 날짜 삽입은 되고 테두리색, 찾기(⌘F), 붙여넣기 일부는 안 된다.
- 09:03 캡컷(웹으로 재현): 11시간짜리 영상 불러오기, 재생, 분할, 삭제는 되지만 화면이 깜빡이고 클립 이동·편집이 사실상 불가능하다. "화면과 프론트만 따 왔다"는 평가.
- 11:09 노션(본격적으로 시도): 로그인, 슬래시 명령, 멘션, 초대, 워크스페이스, 임베드(iframe), 이미지·엑셀 첨부, 히스토리/복원, AI 기능(번역·요약·에이전트)이 동작했다. AI 시스템 프롬프트는 역공학으로 알 수 없어서 따로 만들었다. 서버 쪽 권한·외부 연동은 역공학의 한계(블로커)라 설계에서 뺐다.
- 15:40 방법론: 소스코드는 가져오지 않음 → 노션 사용설명서, 업데이트 로그, 노션을 열 때 생기는 API 요청과 JS 번들로 기능을 추론 → 기능 명세(테스트 케이스) 약 3,000개 → 에이전트를 계속 돌림.
- 16:33 비판적 관찰: 공개되지 않은 페이지가 iframe에 그대로 보이는 것은 인증 처리가 빠졌다는 뜻이다. 보안 디테일은 못 잡았다.
- 17:27 "노션은 10년 걸려 만든 것을 8시간 만에": Claude 5.5로 에이전트 워크플로를 나눠 진행했고, 카탈로그 기능 정합성을 50%→90%로 올리는 라운드를 약 6회 돌렸다.
- 19:08 한계: 로컬에서는 되지만 동시 싱크(누가 어디를 고쳤는지 맞추는 것)와 대규모 페이지 성능 같은 백엔드가 진짜 해자다. 대신 역공학한 뒤 구조를 우리 식으로 최적화할 수는 있다.
- 20:05 결론: 다른 앱은 10점 만점에 약 5점이었지만 노션은 38→96/100. Claude Max 계정 2개를 번갈아 쓰면서 한 계정의 일주일 한도를 다 썼다. 하네스·에이전트 구조화 역량이 결과를 가른다.
- 21:00 Litpage 공개: 노션과 비슷한 UI/UX에 SQLite 기반 로컬/셀프호스팅이며, 내부용·개인 프로젝트용으로 권장.

## 4. 시사점
- 이 영상에서 말하는 "역공학"은 바이너리 디컴파일보다는 **공개 정보로 명세를 만드는 작업(spec mining)**에 가깝다. 성과가 난 노션 사례도 매뉴얼·변경 로그·네트워크 요청으로 기능 카탈로그를 만들고, 개발 에이전트와 분리된 QA 테스트로 반복 검증한 구조였다. REA 자체보다 **요구사항 카탈로그 + 독립 테스트 + 서브에이전트 분업**이 핵심 레버다.
- 우리 쪽 응용: 크루즈 예약/관리 화면처럼 "참고할 기존 서비스가 있는" 내부 도구를 만들 때, 공개 문서 기반 기능 명세 → 수용 테스트 → 에이전트 빌드 방식을 그대로 쓸 수 있다. Litpage(MIT)를 내부 위키/DB 도구로 셀프호스팅해 써 보는 것도 저비용 선택지다.
- 주의: 상용 제품의 약관(역분석 금지 조항), 상표·UI 문구·아이콘 같은 보호 자산 복제 위험이 있다. 리트머스도 공개 전에 이름·문구·디자인을 갈아엎었다. 보안·동시성은 이 방식으로 재현되지 않는다(영상 속 iframe 인증 누락 사례).
- 비용 감각: 수십~100시간 이상의 에이전트 구동과 Max 요금제 여러 개가 필요한 규모다. 소규모로 시도한다면 "기능 50~100개짜리 내부 도구" 정도가 현실적이다.
- 광고성 내용 제거: 리트머스 외주 의뢰·무료 상담 안내, 홈페이지 링크는 요약에서 뺐다.
